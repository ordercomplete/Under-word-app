**Помилка №1 — `--update` з дефолтним `--source` падає на Windows (exit code 1):**
- Команда: `python agent_config/scripts/sync-agent.py --update --dry-run`
- Вивід: `fatal: cannot change to '~/repos/Comfy-smart-lady-agent': No such file or directory`
  → `CalledProcessError: Command '['git', '-C', '~/repos/Comfy-smart-lady-agent', 'pull']' returned non-zero exit status 128`
- Причина: у `main()` (sync-agent.py, рядки ~835 vs ~855) асиметрія розгортання шляху:
  `project_root = Path(args.source).expanduser().resolve()` — тильду розгортає,
  а `subprocess.run(['git', '-C', str(args.source), 'pull'])` отримує СИРИЙ шлях `~/repos/...`.
  Git на Windows не розгортає `~` самостійно.
- Обхід: явний шлях `--source "$HOME\repos\Comfy-smart-lady-agent"`.
- Фікс у центрі: розгортати шлях один раз (`source_expanded = Path(args.source).expanduser()`)
  і використовувати його всюди.

**Помилка №2 — `--update` не перегенеровує `agent-lock.json`:**
- Симптом: після першого `--update` (без `--apply`) файли скопіювались, але `status` показував
  стару версію v1.4.0, `Modified: 7`, `New: 1032` і WARNING «manifest.json changed since install».
- Причина: генерація лока обгорнена умовою `if not args.dry_run and args.apply:` (рядок ~947),
  а прапорець `--update` сам по собі `args.apply` не вмикає. Тобто «режим оновлення» копіює
  файли, але не фіксує нові хеші — лок залишається від інсталяції 15:07.
- Обхід: канонічна команда з Частиї VI інструкції — `--source <шлях> --target . --pull --apply`
  (варіант «Оновлення з явним джерелом»), тобто перезапуск із `--apply`.
- Фікс у центрі: всередині `--update` імпліцитно вмикати apply (або описати це в README).

**Помилка №3 — 249 «привидів» Missing через застарілий manifest центрального репо:**
- Симптом: після коректного `--update --apply` статус: `OK 974 / Modified 0 / Missing 249`.
- Діагностика: усі 249 відсутніх — `agent_config/backup-chat/backup_2026-08-29_14-17-18/**`.
- Причина (ланцюжок):
  1) central v1.4.3 переносить власну бекап-історію в вкладену структуру
     (`git pull` показав rename `backup_2026-08-29_13-50-03 => backup_2026-09-04_17-04-01/...`);
  2) але `manifest.json` центру досі перелічує СТАРІ top-level шляхи backup-chat як `root_files`;
  3) `FileCopier` тихо пропускає файли, яких нема в джерелі;
  4) генератор лока все одно додає записи через `lock.add_file(tp, _file_hash(full), ...)`,
     а `_file_hash()` для неіснуючого файлу повертає `""` — записи з порожнім хешем;
  5) `cmd_status` рахує їх Missing.
- Виправлення на хості (без видалення файлів): скрипт-очистка прибрала 249 застарілих
  записів із `agent-lock.json` → `Missing: 0`. Залишок: `New: 249 (in manifest, not installed)`
  — це ті самі мертві шляхи В САМОМУ manifest; зникнуть лише після того, як центр
  виконає `python agent_config/scripts/update-manifest.py --apply` і закомітить manifest.
- Фікс у центрі: перегенерувати manifest + у `main()` не додавати в лок записи,
  де `src` не існує (skip + попередження).

**Помилка №4 (дрібна) — підкоманда `status --verbose` парситься неправильно:**
- Симптом: `python agent_config/scripts/sync-agent.py status --verbose` →

- Обхід: `python agent_config/scripts/sync-agent.py status . --verbose`.
