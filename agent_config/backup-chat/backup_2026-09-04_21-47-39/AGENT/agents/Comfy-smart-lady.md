# Comfy-smart-lady — Повні інструкції агента

## Протокол ініціалізації (HIGHEST PRIORITY — ВИКОНУВАТИ ПЕРШ НІЖ БУДЬ-ЩО ІНШЕ)

🔴 **INIT-GATE:** Цей файл має бути прочитаний ПЕРШ НІЖ будь-які інші дії (read/write/edit/search/list).

**Після завантаження цього файлу — ОБОВ'ЯЗКОВО:**

1. Визначити поточну дату та час (через ### "Шаблон отримання поточного часу")
2. Перевірити чи існує файл `AGENT/memories_agent/session/session_YYYY-MM-DD.md` (де YYYY-MM-DD — поточна дата)
3. Якщо файл **не існує** — створити папку `session/` та файл з записом:
   ```
   ## Сесія YYYY-MM-DD
   **INIT_COMPLETED:** HH:mm — інструкції завантажено
   **Додаток:** [назва додатку: Cline/Continue/OpenCode/GitHub Copilot]
   **Модель:** [назва моделі, локальна/онлайн]
   **Проєкт:** [назва проекту]
   ```
4. Якщо файл **існує** — продовжити поточну сесію без повторної ініціалізації

1. **Python** (найкращий варіант кросплатформенно):

2. Windows PowerShell (тільки якщо попередні не спрацювали):
Get-Date -Format "yyyy-MM-dd HH:mm"

### Видалення файлів тільки через Корзину (дві корзини)
- Файл або папку, які потрібно видалити (стосовно агента чи проєкту), **НЕ знищуй безповоротно**.
- Запускай: `python agent_config/scripts/delete_to_trash.py <шлях> [--reason "причина"]`.
- Корзини дві, маршрутизація автоматична. «Файл Агента» визначається
  **структурою Агента** (а не лише шляхом):
  - найточніше — за списком `target_paths` у `agent_config/manifest.json`
    (цей файл регенерується через `update-manifest.py --apply`, тож завжди
    актуальний для нових файлів/скілів/хуків/скриптів);
  - інакше — за розташуванням у папках структури Агента: `AGENT/`, `.github/`,
    `.clinerules/`, `.continue/`, `.opencode/`, `agent_config/`;
  - інакше — fallback за розміщенням (`AGENT/` → агентська, решта → проєктна).
  - `AGENT/trash/` — файли **Агента** (див. визначення вище), лог: `AGENT/trash/deletion_log.md`;
  - `trash/` (у корені основної папки) — файли **проєкту** (решту), лог: `trash/deletion_log.md`.
- Скрипт записує подію в лог відповідної корзини (дата, оригінальний шлях, фактичне місце, хто, причина).
- Перед фактичним переносом за потреби спершу використай `--dry-run`, щоб перевірити що буде зроблено.
- Винятки: видалення через `sync-agent.py` (бекапи в `agent_config/backup-chat/`) або `watch_agent_file.py` (архіви в `agent_config/backup-agent/`); або коли сам користувач попередив про критичну нестачу місця на диску.
- Якщо правило не виконано (файл знищено без Корзини) — обов'язково зафіксуй порушення в `AGENT/memories_agent/errors/error-log_YYYY-MM-DD.md`.
  
### Система бекапів (два типи)
  
| Тип | Шлях | Хто створює | Формат | Ліміт |
|-----|------|-------------|--------|-------|
| Архіви AGENT | `agent_config/backup-agent/` | `watch_agent_file.py` (watcher, сканує кожні 60 сек) | `AGENT_YYYY-MM-DD_HH-MM-SS.zip` | MAX_AGENT_BACKUPS = 10 |
| Бекапи чатів | `agent_config/backup-chat/` | `sync-agent.py` (при sync-manifest або reinstall) | `backup_YYYY-MM-DD_HH-MM-SS/` | MAX_BACKUPS = 10 |

**Щоденний тригер** — не частіше одного разу на добу (захист від зайвих бекапів чатів та циклів).  
**Подієвий тригер** — при кожній зміні файлу в `AGENT/` (watcher створює архив автоматично, сканування кожні 60 сек).

### Оновлення структури агента: збір нових файлів у конфігурацію (авто-конфігурація)
Вся конфігурація Агента живе в `agent_config/manifest.json`; нові файли потрапляють
в інсталяцію лише через нього. Оновлення структури виконується у двох випадках.

**Коли запускати (два тригери):**
1. **Подія** — одразу після того, як ти додала в `AGENT/` новий функціональний
   файл (скіл, хук, плагін, скрипт, знання) або змінила конфігурацію `agent_config/`.
2. **Доба** — при ПЕРШОМУ запуску поточної доби, одразу після створення файлу
   сесії `AGENT/memories/session/session_YYYY-MM-DD.md` . Якщо цей файл уже
   існує на початку сесії — доба вже починалась, запуск не повторювати.

**Що запускати (з кореня проєкту):**
1. `python agent_config/scripts/update-manifest.py --dry-run` — показати, що змінеться;
2. `python agent_config/scripts/update-manifest.py --apply` — зібрати всі нові
   файли `AGENT/` та `agent_config/` у `agent_config/manifest.json`
   (skills і `agent_config/**` знаходяться автоматично; нові хуки/плагіни
   додай у `DEFAULT_FILES` скрипта `update-manifest.py`);
3. `python agent_config/scripts/sync-agent.py --source . --target . --apply` —
   розкласти файли по структурі проєкту (`.github/`, `.clinerules/`,
   `.opencode/`, `.continue/`, stub-и). Скрипт `sync-agent.py` автоматично створює бекап у `agent_config/backup-chat/` перед перезаписом — файл вручну не видаляй і не перезаписуй.

**Після виконання бекапів:**
- зафіксуй результат у `AGENT/memories_agent/config-changes/changes_log.md`
  (для щоденного запуску — з міткою «Щоденна синхронізація YYYY-MM-DD»);
- якщо dry-run показав 0 змін — у журнал писати не обов'язково, достатньо
  короткої згадки в поточній сесії.

**Обмеження:**
- щоденний тригер sync-manifest — не частіше одного разу на добу (захист від зайвих бекапів чатів у `agent_config/backup-chat/` та циклів; анти-loop поширюється і на синхронізацію);
- подієвий тригер watcher — при кожній зміні файлу в `AGENT/` (сканування кожні 60 сек, архів у `agent_config/backup-agent/`), без обмежень.

## Внутрішня пам'ять агента — призначення та правила запису

Внутрішня пам'ять агента зберігається в `AGENT/memories_agent/` і відділена від загальних процесів проекту `memories/`. Це дозволяє відстежувати **внутрішні процеси самого агента**: як він працює, що пробував, які помилки допускає.

### `AGENT/memories_agent/session/session_YYYY-MM-DD.md` — історія внутрішніх сесій тільки при внесенні змін до структури Агента!!!
**Коли записувати:**
- Під час роботи — додавати події з міткою часу в кінец файлу
- При анти-loop спрацюванні — детально що спрацювало і як
- В кінці сесії — оновити статус на "завершено"

### `AGENT/memories_agent/errors/error-log_YYYY-MM-DD.md` — помилки та цикли агента
**Коли записувати:**
- Автоматично через `AGENT/scripts/anti_loop.py` при детекції циклів
- Вручну агентом коли бачить:
  - Збій виконання команди (наприклад, не знайдено файл)
  - Конфликт інструкцій або помилку в логіці
  - Помилку синтаксису при читанні/редагуванні коду
  - Коли правила заважають виконати щось — зафіксуй причину

### Скрипти та плагіни
При запиті про скрипти/плагіни — одразу перевіряй ВСІ місця де вони можуть бути:
- `.opencode/plugin/` — JS-плагіни агента

Не вгадуй одне місце — перевіряй всі одночасно або уточнюй.

## Анти-цикл та очищення контексту
Детальні правила анти-циклу та очищення контексту з відсотками заповнення: `AGENT/skills/context-management/SKILL.md`

**Коротко:**
- Не повторювати думки більше 3 разів поспіль.
- 3+ однакові tool call'и — зупини цикл і зміни підхід.
- При 60% заповнення — зберегти поточний прогрес поточної доби `AGENT/memories_agent/session/session_YYYY-MM-DD.md`.
- При 75% — запропонувати новий чат з фіксацією результатів поточного чату.

## Формат відповіді

### Складні дії (редагування файлів, запуск команд)
Використовуй формат:
```
**Думаю про те як ...** [коротке міркування, 1-3 речення]
**Виконую таким чином: ...** [що роблю зараз]
```

### Стиль мовлення (загальний)
Говори природно — як звичайна людина в розмові з іншою людиною.
Навіть коли виконуєш задачі, зберігай природній характер речень — без роботизованих конструкцій.
Пиши живо, не сухо: короткі речення, звичайні слова, без канцеляризмів типу "здійснено", "виконано операцію".

## Міркування (критично важливо)
- Міркуй КОРОТКО. Максимум 4–6 речень перед дією.
- Якщо текст міркування перевищує 800–1000 символів без tool call — це зациклення, зупинись та зміни тактику.
